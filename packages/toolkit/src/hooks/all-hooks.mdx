# All hooks

Every surface in Real Life Stack asks hooks, never the connector. This page lists all hooks the toolkit exports, with the question each answers and what happens when the connector lacks the capability.

**The column "without capability" is the important one.** Reading hooks answer empty: "no groups", "nobody signed in", "zero comments" are true answers, not errors. Writing hooks fail on the call, not on preparation — any surface may build a button. Where it says "throws on render" nevertheless, that is intended: the surface cannot exist without that capability.

Living examples are under [Foundations → Hooks](?path=/story/rls-foundations-hooks--read).

*This list is kept by hand until it is generated from each hook's documentation comment (plan D2), which cannot drift from the exports.*

## Read items

| Hook | Answers | Question it answers | Without capability |
|---|---|---|---|
| `useItems(filter?)` | `{data, isLoading}` | Which items match this filter, and is the list still arriving? | — |
| `useItem(id)` | `{data, isLoading}` | Does this one item exist, and is "not found" already decided? | — |
| `useItemsWithDraft(filter?)` | `{data, isLoading}` | The same list, with the draft being typed already in it as a card. | — |
| `useModuleFilteredItems(items)` | `Item[]` | Exactly what the toolbar in the module head promises: filter plus search text. | throws without `FilterProvider` |
| `useActivity(scope)` | `{data, supported}` | What happened in this space recently? | empty, `supported: false` |
| `useNotifications()` | `{notifications, badgeCount, …}` | What is new for me, and how much is unread? | empty |

## Write items

| Hook | Answers | Question it answers | Without capability |
|---|---|---|---|
| `useCreateItem()` | `{mutate}` | Create a new item. | throws on call |
| `useUpdateItem()` | `{mutate}` | Change an existing item. | throws on call |
| `useDeleteItem()` | `{mutate}` | Delete an item. | throws on call |
| `useItemEditor(options)` | `{isOpen, mode, submit, remove, …}` | Open the composer and save an input as an item, including its space. | throws on call |
| `useDraftItem()` | `Item \| null` | What is someone typing right now that modules should preview? | `null` without provider |
| `useSetDraftItem()` | `(draft) => void` | Publish or discard the running draft. | no-op |
| `useUnsavedChanges()` | `{dirty, setDirty} \| null` | Are there unsaved inputs that leaving must intercept? | `null` without provider |
| `useSetUnsavedDirty()` | `(dirty) => void` | Report that something unsaved sits in the form. | no-op |

## Pairs easily confused

- `useCurrentUser` and `useOptionalCurrentUser` differ only in whether a missing sign-in throws or yields `null`. The same pattern with `useConnector`.
- `useReactions` already carries in `reactions[].userIds` what `useReactionUsers` fetches again.
- `useCommentCount` is the cheap half of `useComments`.
- `useItems` and `useItemsWithDraft` are the same list, the latter with the running draft.
- `useIsMobile` and `useIsCompact` are the same mechanism with a different threshold: 768px for navigation, 1024px for the panel shape.
